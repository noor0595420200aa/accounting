# نظام إدارة الصالة والمغسلة والملعب

نظام محاسبي وإداري لثلاثة أنشطة: صالة الأفراح، والمغسلة والخدمات، وملعب كرة القدم.
الواجهة عربية بالكامل (RTL) وتعمل على الهاتف والكمبيوتر، ويمكن تثبيتها على الهاتف كتطبيق (PWA).

## التشغيل

```bash
npm install
npm start            # http://localhost:3000
npm test             # اختبار شامل لكل العمليات المحاسبية
```

أول دخول: المستخدم `admin` وكلمة المرور `admin123`، ويطلب النظام تغييرها فوراً.
يمكن تحديد كلمة مرور أولية مختلفة بالمتغير `ADMIN_PASSWORD` قبل أول تشغيل.

أو باستخدام Docker:

```bash
docker build -t accounting .
docker run -d -p 3000:3000 -v accounting-data:/data -e APP_SECRET=ضع-نصاً-سرياً-طويلاً accounting
```

| المتغير | الوظيفة |
|---|---|
| `PORT` | منفذ الخادم (افتراضي 3000) |
| `DATA_DIR` | مجلد قاعدة البيانات والتقارير والنسخ الاحتياطية (افتراضي `./data`) |
| `APP_SECRET` | مفتاح تشفير توكن تيليجرام (إن لم يُحدد يُنشأ ملف `data/secret.key`) |
| `CHROME_PATH` | مسار Chrome/Chromium لإنشاء PDF (يُكتشف تلقائياً إن أمكن) |
| `ADMIN_PASSWORD` | كلمة مرور المدير الأولية |

> كل البيانات في مجلد `DATA_DIR`. انسخه احتياطياً أو استخدم النسخ الاحتياطي التلقائي من الإعدادات.

## أنواع الحسابات

| النوع | الصلاحيات |
|---|---|
| **مدير** | كل شيء: كل الأقسام، الإلغاء، الحسابات، الديون، المستخدمون، الإعدادات، إرسال التقارير. |
| **موظف قسم** | يسجل حجوزات وطلبات ودفعات ومصروفات **وديون** قسمه فقط. الإلغاء للمدير إلا إذا سُمح من الإعدادات. |
| **مشاهد (المالك)** | يرى الإحصائيات والخزن والديون والتقارير وكشوفات الحساب لكل المنشآت، وينشئ ملفات PDF وExcel. لا يستطيع التسجيل أو التعديل أو الإلغاء، والخادم يرفض أي محاولة. |

## الترقيم

كل منشأة لها تسلسل مستقل برمزها: **A** للصالة، **U** للمغسلة، **D** للملعب، **R** للحسابات العامة.
كل حجز أو طلب أو دفعة أو مصروف أو تمويل يأخذ الرقم التالي في منشأته (A100، A101، …).
يمكن البحث بأي رقم من شريط البحث أعلى الصفحة، ويمكن تغيير الرموز ورقم البداية من الإعدادات.

## المبادئ المحاسبية المطبقة

- **دفتر حركات واحد** (`txns`) هو مصدر كل الأرصدة. لا يوجد رصيد مخزن يمكن أن يختلف عن الحركات.
- المبالغ تخزن كأعداد صحيحة (× 100) لتجنب أخطاء الكسور.
- **لا حذف للعمليات المالية**: الإلغاء يحفظ العملية الأصلية والسبب ومن ألغاها، ولا تدخل في الأرصدة.
- **منع التكرار**: كل نموذج يرسل مفتاحاً فريداً، فالضغط المزدوج لا يسجل الدفعة مرتين.
- **الرصيد حسب المكان**: كل خزنة تتكون من حسابات (خزنة، بنك، حساب موظف…). المال الذي مع الموظف جزء من رصيد المنشأة، ويظهر مكانه بالاسم.
- **الديون ليست نقداً**: ديون زبائن المغسلة والمتبقي على الحجوزات تُعرض منفصلة عن الرصيد النقدي.
- **الديون علينا**: لا يوجد تمويل تلقائي من أي حساب. الدين يُسجل على المنشأة باسم الدائن (لمين ندين) وسببه، ويُحدد هل وصل مال للصندوق أم كان شراءً بالدين.
  كل سداد يُسجل مع سببه ومن وين طلع المبلغ. الحالة تظهر: قائم، مسدد جزئياً، أو **تم السداد**. سداد الدين ليس مصروفاً.
- **صافي الأصول** = اللي ضل + ديون الزبائن لنا − الديون علينا اللي لسا ما انسددت.

## القواعد التشغيلية

- **الصالة**: العربون إلزامي. فترتان (مسائية افتراضياً وصباحية). يُمنع حجز نفس الفترة مرتين، ويصبح التاريخ متاحاً بعد الإلغاء.
- **الملعب**: الساعات والإجمالي تُحسب تلقائياً، ويُدعم الحجز الذي يتجاوز منتصف الليل، ويُمنع تداخل الأوقات.
- **الإلغاء**: إرجاع كامل المبلغ، أو الاحتفاظ به، أو خصم جزء وإرجاع الباقي.
- **المغسلة**: الحالة (مدفوع / جزئي / غير مدفوع) والدين يُحسبان تلقائياً من الدفعات. تسديد الدين يوزَّع على أقدم الطلبات.
- **الإلغاء للموظفين** معطل افتراضياً ويمكن تفعيله من الإعدادات.

## حسابات الدفع والجرد

المدير يضيف أي حساب دفع من "الخزن والحسابات ← إضافة حساب دفع"، مثل **بنك فلسطين — فلان**: اسم الحساب، واسم صاحبه، والنوع، والمنشأة.
صفحة الخزن فيها **جرد حسابات الدفع**: لكل حساب كم دخل عليه، وكم خرج منه، وكم ضايل فيه. الجرد لليوم، أو آخر 7 أيام، أو هذا الشهر، أو من البداية، أو أي فترة تختارها.
نفس الجدول موجود في كل تقرير PDF وفي رسالة تيليجرام المرافقة لكل ملف.

## الرصيد وطرق الدفع

لكل منشأة ثلاثة حسابات جاهزة: **كاش**، **بال باي**، **جوال باي**. يمكن إضافة غيرها، مثل حساب موظف (يُحسب ضمن الكاش) أو حساب بنكي.
عند تسجيل أي دفعة يضغط الموظف على المكان الذي وصلت إليه.

كل كشف وكل صفحة خزنة مرتبة هكذا:
1. **الرصيد**: إجمالي اللي انجمع، وإجمالي اللي طلع، واللي ضل.
2. **وين وصلت المصاري**: التقسيم حسب الطريقة، مثل 1000 بال باي و500 جوال باي و1000 كاش.
3. **التوضيح**: كل معاملة بنوعها (عربون، دفعة تكملة…) وتاريخ الدفع وتاريخ الحجز وتاريخ الفرح أو اللعب ووين وصلت والموظف.

## رسائل تيليجرام الفورية

لكل عملية رسالة فورية بقالب موحد: حجز، دفعة، طلب، مصروف، إيداع، إلغاء، تعديل حجز، دين، أو سداد دين. تحتوي الرسالة على الرقم والتفاصيل، ووين وصل المبلغ أو من وين طلع، ورصيد المنشأة الآن، ومن سجّلها، والوقت.
الرسالة تُحفظ مع العملية نفسها: إذا فشلت العملية لا تُرسل رسالة، وإذا تعطل الاتصال تُعاد المحاولة.

## التقارير وتيليجرام

- **جرد تلقائي**: يومي (كل ليلة عن اليوم المنتهي)، وأسبوعي، وشهري (أول الشهر عن الشهر الماضي).
- **كل شخص يختار شو يوصله** من صفحة المستخدمين: اليومي، أو الأسبوعي، أو الشهري، أو رسالة لكل عملية. مثلاً المالك الأسبوعي فقط.
- **زر الإرسال اليدوي للمدير**: يختار المدة ويختار مين يوصله التقرير.


**كل منشأة كشف مستقل تماماً**: الصالة ملف، والمغسلة ملف، والملعب ملف، والملخص الإجمالي ملف منفصل. تيليجرام يستقبل كل ملف لحاله.


- **تقرير يومي تلقائي** الساعة 00:05 عن اليوم المنتهي (00:00 — 23:59)، مع ملخص تراكمي للشهر والسنة، ويُرسل PDF إلى تيليجرام.
- **تقرير أسبوعي تلقائي** عن آخر 7 أيام (اليوم والوقت من الإعدادات).
- **تقارير يدوية**: يومي، آخر 7 أيام، شهري، سنوي، بين تاريخين، أو شامل. تُصدَّر PDF أو Excel.
- **كشف حساب شامل PDF**: لكل المنشآت أو منشأة أو حساب أو موظف، ولأي فترة، مع الرصيد المتحرك.
- إذا سُجلت عملية بتاريخ يوم سبق إرسال تقريره، يُعلَّم التقرير كـ"تغيّرت بياناته" ويظهر تنبيه للمدير مع زر "تحديث وإرسال".
- فشل الإرسال يُسجل ويظهر كتنبيه، ويعيد النظام المحاولة تلقائياً حتى 3 مرات.

**الإعداد** (الإعدادات ← تيليجرام):
1. أنشئ بوتاً من @BotFather وضع التوكن.
2. يرسل المدير والمالك أي رسالة للبوت، ثم اضغط "جلب المحادثات" لترى رقم كل واحد.
3. ضع رقم كل شخص في حسابه من صفحة المستخدمين. التقارير تصل للمدير والمالك معاً، ويمكن إضافة مجموعة أيضاً.
4. اضغط "إرسال رسالة اختبار للجميع".

إذا فشل الإرسال لشخص واحد، يصل للباقين ويظهر تنبيه. إعادة المحاولة التلقائية لا تكرر الملف لمن استلمه.

```
  db.js            قاعدة البيانات (SQLite) والبيانات الأولية
  ledger.js        قلب المحاسبة: تسجيل الحركات والأرصدة والإلغاء
  routes/          hall, field, laundry, finance, core, reports, admin
  reports/         بناء بيانات التقارير، HTML، PDF، Excel
  scheduler.js     التقارير التلقائية والنسخ الاحتياطي
  telegram.js      الإرسال عبر بوت تيليجرام
public/            الواجهة (بدون أدوات بناء)
test/smoke.js      اختبار شامل
```
